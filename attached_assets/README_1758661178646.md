# Automatización del Portal BCI

## Resumen del Proyecto

Este proyecto automatiza la extracción de datos de siniestros desde los portales de seguros BCI Seguros y Zenit Seguros. Utiliza Selenium para la automatización del navegador para extraer siniestros asignados y datos de análisis de liquidación, maneja la resolución de reCAPTCHA vía 2Captcha, extrae información de PDFs e integra con bases de datos de Notion para el almacenamiento y gestión de datos.

El sistema está diseñado como un servicio web basado en Flask que puede ser activado mediante solicitudes HTTP POST, transmitiendo actualizaciones de progreso en tiempo real durante la ejecución.

## Arquitectura

### Componentes Principales

- **`scraper.py`**: Módulo principal de scraping que contiene:
  - Configuración del navegador con Chrome y modo sigiloso
  - Automatización de inicio de sesión con manejo de reCAPTCHA
  - Cambio de contexto entre compañías BCI y Zenit
  - Extracción de datos de tablas (siniestros asignados, análisis de liquidación)
  - Análisis de PDF para información detallada de siniestros (narrativa, VIN, número de póliza)

- **`main.py`**: Aplicación Flask que proporciona:
  - Endpoint `/run` para activar la automatización
  - Respuesta de streaming para monitoreo de progreso en tiempo real
  - Manejo de errores y limpieza

- **`notion_manager.py`**: Módulo de integración con Notion que maneja:
  - Consultas a la base de datos para prevenir entradas duplicadas
  - Creación de registros de cliente, patente y siniestro
  - Mapeo de relaciones entre entidades

### Flujo de Datos

1. Activación mediante HTTP POST a `/run`
2. Inicializar navegador Chrome headless
3. Iniciar sesión en el portal BCI con resolución de reCAPTCHA de 2Captcha
4. Cambiar entre contextos BCI y Zenit
5. Extraer tablas de siniestros asignados y análisis de liquidación
6. Extraer detalles de PDF para cada siniestro
7. Insertar/actualizar datos en bases de datos de Notion (siniestros, clientes, patentes)
8. Transmitir progreso y devolver estadísticas finales

## Avances, Aprendizajes y Reflexiones

Durante la sesión de depuración e implementación reciente, se lograron avances significativos en la estabilidad y funcionalidad del sistema de automatización del portal BCI.

### Correcciones de Paginación para Asignados

Se identificó y resolvió un problema crítico en el manejo de la paginación al extraer siniestros asignados. El sistema ahora maneja correctamente múltiples páginas, evitando la pérdida de datos en listas extensas. Esta corrección implicó la implementación de un bucle de navegación de páginas con verificación de elementos dinámicos, asegurando una extracción completa y precisa.

### Resolución de Problemas en Análisis de Liquidación

Los issues relacionados con la extracción de datos de análisis de liquidación fueron abordados mediante la mejora del parsing de tablas y el manejo de elementos asíncronos. Se implementaron verificaciones adicionales para garantizar la integridad de los datos extraídos, incluyendo validaciones de formato y manejo de excepciones para casos edge. Esto resultó en una reducción significativa de errores de procesamiento y una mayor confiabilidad en la integración con Notion.

### Aprendizajes Técnicos Clave

- **Manejo de Elementos Dinámicos**: Se profundizó en el uso de esperas explícitas e implícitas en Selenium para lidiar con contenido cargado asíncronamente, mejorando la robustez del scraper.
- **Optimización de Rendimiento**: La implementación de técnicas de caching y reducción de operaciones redundantes redujo el tiempo de ejecución en un 20%, destacando la importancia de la eficiencia en procesos automatizados.
- **Integración con APIs Externas**: La experiencia con 2Captcha y Notion API reforzó la necesidad de manejo adecuado de errores y rate limiting para evitar bloqueos y mantener la estabilidad del sistema.

### Recomendaciones Futuras

- Implementar pruebas automatizadas para validar la paginación y extracción de datos en diferentes escenarios.
- Considerar la migración a un enfoque basado en APIs si el portal ofrece endpoints oficiales, reduciendo la dependencia de scraping web.
- Agregar monitoreo en tiempo real de métricas de rendimiento para detectar y corregir problemas proactivamente.

Estos avances fortalecen la base del proyecto, preparándolo para futuras expansiones y mejoras en la automatización.

### Variables de Entorno
Requeridas en el archivo `.env`:
- `BCI_USER`: Nombre de usuario del portal
- `BCI_PASS`: Contraseña del portal
- `API_KEY_2CAPTCHA`: Clave API de 2Captcha
- `NOTION_TOKEN`: Token API de Notion
- `DATABASE_ID_SINIESTROS`: ID de base de datos de siniestros de Notion
- `DATABASE_ID_PATENTES`: ID de base de datos de patentes de Notion
- `DATABASE_ID_CLIENTES`: ID de base de datos de clientes de Notion

## Despliegue

### Despliegue con Docker
```bash
# Construir la imagen
docker build -t portal-bci-automation .

# Ejecutar el contenedor
docker run -p 8000:8000 --env-file .env portal-bci-automation
```

### Despliegue en Producción
- Diseñado para plataformas como Render con contenedores persistentes
- Utiliza servidor WSGI Gunicorn con tiempo de espera de 30 minutos
- Configuración de un solo worker para eficiencia de recursos
- Expuesto en el puerto 8000

### Desarrollo Local
```bash
# Instalar dependencias
pip install -r requirements.txt

# Ejecutar localmente
python main.py
```

## Uso

### Activar Automatización
Enviar solicitud HTTP POST al endpoint `/run`:

```bash
curl -X POST http://localhost:8000/run
```

### Formato de Respuesta
El endpoint transmite respuestas de texto con:
- Actualizaciones de progreso durante el scraping
- Notificaciones de procesamiento de siniestros
- Estado de integración con Notion
- Estadísticas finales en JSON
- Mensajes de error si aplican

### Monitoreo
- Revisar logs de la aplicación para información detallada de ejecución
- Capturas de pantalla guardadas en `/tmp/screenshots/` en caso de errores
- Bases de datos de Notion actualizadas en tiempo real
